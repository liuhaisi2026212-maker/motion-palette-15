# 十五画境 · MG 动画手艺书

这不是模板库。这里写的是**怎么用代码把一种风格做对味**：每种风格靠什么被一眼认出来、关键手法的具体参数、最容易做砸的地方、做完怎么检查。你读完以后，按用户的主题自己写代码，做一支新片子。

模型越强，做出来越好；但只要照着流程走、用好脚手架，一般的模型也能做到「像样」。

## 先判断你走哪条路

- **能写代码、能运行命令**（Claude Code、Codex、Cursor、带代码执行的国产 Agent 等）：按「完整流程」做，自己写画面代码，用脚手架导出 MP4。
- **只能聊天、不能运行代码**：照样按流程写出完整代码（一个 HTML 文件夹），告诉用户怎么打开和导出（见 `references/02-渲染与导出.md` 最后一节）。不要说「视频已生成」。

再判断你的能力档位（拿不准就按「一般」）：
- **强**：读通用手艺 + 风格卡的全部内容，可以自己设计镜头、写着色器、做复杂角色。
- **一般**：只读 `references/05-一般模型怎么做.md` 和对应风格卡的「最小可行做法」，直接改 `starter/` 里的骨架，**一次只用 2～3 个手法，把它们做干净**，比堆一堆半成品好得多。

## 完整流程（每一步都不要跳）

1. **问清楚**：主题、给谁看、想让观众记住哪一句话、时长（默认 10～20 秒）、横屏还是竖屏、有没有品牌名或素材（照片、logo）。用户没说的，按默认值走，并在交付时说明。
2. **选风格**：看 `references/styles/00-选风格.md`。用户点名的就用点名的；没点名的给 2～3 个候选，各一句理由。
3. **写节拍表**（还不写代码）：按秒写出 钩子 → 推进 → 高潮 → 收尾。每一拍写：画面里是什么、发生什么变化、屏幕上什么字、什么声音。规则见 `references/00-工作流程.md`。
4. **读风格卡**：`references/styles/<风格>.md`。**先读「最容易做成不像的原因」那一节**——那是对照原版总结的版式、零件和戏，照着搭骨架；再把「必备元素」逐条对到节拍表上，缺哪个补哪个。宁可零件多、画面满，不要几个元素飘在空白里。
5. **先做静帧**：用脚手架搭好页面，只做 4～6 个关键时刻的静止画面，截图自己看。构图、字号、配色、留白都过关了再加动画。
6. **再做动画**：按 `references/01-通用手艺.md` 的缓动、错峰、预备、回弹参数来，一次只动一个主体。
7. **配声音**：用脚手架的合成器写配乐和音效，卡在画面的节拍点上。
8. **导出并自查**：导出 MP4，按 `references/04-自查与评审.md` 抽帧检查，改掉问题再交付。
9. **交付**：MP4 + 源码文件夹 + 一段说明（用了什么风格、每个必备元素在哪一秒、已知的不足、字体 / 图片 / 音乐的来源清单）。

## 底线

- **原创**：风格要学到位——版式、零件、节奏、质感都照风格卡来，这不是抄；但主体、文案、角色、具体构图和配乐必须是自己的。品牌名用用户自己的，没有就编一个。
- **素材合法**：字体、图片、音频只用可商用的（OFL、CC0、公有领域、用户自己的）；中文字体把 OFL 的 `"Noto Sans SC"` 写在最前面；不放别人的商标和 IP 角色。交付时附来源清单，细则见 `references/06-版权与素材.md`。
- **确定性**：每一帧只由时间 t 决定（不用 `Date.now()`、不用不带种子的随机数），否则导出会抖、会对不上。
- **诚实**：没导出成功就说没成功；做不到的风格特征就写进「已知不足」。
